
# SaltStocks Developer Guide

## Project layout
- `app/main.py` — FastAPI routes, forms, SKU logic
- `app/db.py` — DB helpers / connection
- `app/schema.sql` — schema for initial DB creation (and reference)
- `app/migrate.py` — safe migration script for adding new columns/tables
- `app/templates/` — HTML templates
- `data/saltstocks.db` — local SQLite database (ignored by git)
- `data/backups/` — timestamped backups (ignored by git)

## Local dev run
```bash
cd ~/Documents/Saltstocks
source .venv/bin/activate
uvicorn app.main:app --reload
```

Git workflow (recommended)
Make changes locally
Test locally
Commit a meaningful checkpoint
Push to GitHub
Useful commands:

```
git status
git diff
git add .
git commit -m "Describe change"

```

Branch workflow for bigger features:

```
git checkout -b feature/<name>
```

SKU generation rules (current)
SKU is read-only.
SKU is created on item creation if blank/null.
Format:
{COMPANY}-{CODE}-{SEQUENCE}
SEQUENCE increments per (COMPANY + CODE) using sku_counters.
sku_counters
Keyed by:
company (GV/UM)
code (FUNKO/LEGO/NECA/etc.)
Tracks:
next_seq integer
Data safety rules (current)
Database file is not committed to git.
Backups are created via UI and stored locally.
Migrations
If schema changes are needed:
Prefer additive changes (ALTER TABLE ADD COLUMN)
Use app/migrate.py for one-time migrations
Avoid destructive migrations unless you have a clear backup/restore plan
Run migration:

```
source .venv/bin/activate
python app/migrate.py
```

## Standard Git + Codex Patch Workflow (SOP)

This project uses a branch-based workflow for non-trivial changes
(features, schema changes, bulk edits, imports, etc.).

The app always runs from the local filesystem.
GitHub is used for version history, backup, and collaboration.

### SOP: Apply Codex Patch on a Feature Branch

Use this workflow whenever adding a patch or feature generated by Codex.

#### 1) Start from a clean `main`

```bash
cd ~/Documents/Saltstocks
git switch main
git pull
git status
```

You should see:

> working tree clean

If not, commit or restore changes before continuing.

---

#### 2) Create a feature branch

Use a descriptive branch name:

```bash
git switch -c docs/anchor-toc
```

Branch naming conventions:

* `docs/*` — documentation-only changes
* `feat/*` — new features
* `fix/*` — bug fixes
* `chore/*` — refactors / internal cleanup

---

#### 3) Apply the Codex patch locally

In Codex:

* Select **Unified diff**
* Click **Copy patch** (or **Copy git apply**)

In Terminal (Mac clipboard → file):

```bash
pbpaste > codex.patch
git apply --check codex.patch
git apply codex.patch
```

If `git apply --check` produces no output, the patch is safe to apply.

---

#### 4) Sanity checks

```bash
python -m py_compile app/main.py
git diff
```

* Ensure no syntax errors
* Review changes before running the app

---

#### 5) Quick smoke test

```bash
uvicorn app.main:app --reload
```

* Load the app in the browser
* Click through normal flows for ~30 seconds
* Stop server with `Ctrl + C`

---

#### 6) Commit and push the branch

```bash
git add .
git commit -m "docs: add main.py anchors + TOC"
git push -u origin docs/anchor-toc
```

At this point:

* Changes are saved locally
* Backed up on GitHub
* Isolated from `main` until merged



### Important Notes

- The application always runs from local files in `/Documents/Saltstocks`
- `git commit` saves a checkpoint locally
- `git push` updates GitHub only
- GitHub never updates the local app unless `git pull` is run

If a change exists locally, the app sees it immediately.
